Version 0.2.0 is prepared but not published yet, so none of this is in the download on this site until it is. The list below sums up the release; the entry "Next release (in progress)" below it holds the details of the smaller changes. The macOS build stays unsigned.

### New

- **Official plugins, on by default.** The graph, gallery, favourites, frames and presenting, formula, Mermaid, PDF import, table and Markdown import features now run on the plugin platform (API 0.29.0). Each switches off in Settings (Extensions or Plugins), and an off plugin costs nothing. Auto-export is also official, but off until you enable it. See [Plugins](/docs/plugins/).
- **Markdown notes and Obsidian vaults.** `.md` notes open in a tab with a reading view and an editor, with Obsidian's `[[links]]`. Obsidian vaults open in place, and **Import Obsidian vault…** converts notes, links, images and `.excalidraw.md` drawings into drawings, never changing the source. See [Notes and Obsidian](/docs/notes-and-obsidian/).
- **Profiles.** Named sets of settings, keys, theme and extensions that you switch between, per run or per vault. See [Profiles](/docs/profiles/).
- **Backup and restore.** `Vault: Back up vault…` writes a checked zip of your drawings, notes and attachments in the background; scheduled backups are off until you ask. See [Vault and files](/docs/vault/#back-up-and-restore).
- **Several libraries.** Each `.excalidrawlib` file is its own section in the library panel.
- **Synced folders.** Conflict copies from iCloud Drive, Dropbox, Syncthing and OneDrive get a badge and can be compared with the original. See [Vault and files](/docs/vault/#vaults-in-synced-folders).
- **Focus mode.** One toggle hides everything but the canvas and the drawing toolbar.
- **Themes catalogue.** **Settings → Appearance → Install more themes…** browses the community list at [github.com/Vaultdraw/themes](https://github.com/Vaultdraw/themes). Downloading asks once and can be turned off. See [Themes](/docs/themes/#community-themes).
- **Linux builds.** `.deb` and AppImage packages for x86_64 and arm64, with the `vaultdraw` command and PDF import. See [Install](/docs/install/#linux).
- **AI tools and plugin commands from Terminal.** `vaultdraw mcp` stays off until `ai.enabled`. `vaultdraw plugin commands` and `vaultdraw plugin run` list and run plugin commands.

### Data safety and security

- Quitting, closing the window and switching vault write every open note first.
- Renaming or moving a drawing onto a name that differs only by accent or Unicode form can no longer replace another file. Saving never replaces a read-only or Finder-locked drawing.
- Read-only drawing files open in view mode with a banner and **Save a copy**.
- Repeated failed saves keep one recovery copy per drawing, so recovery storage no longer fills up.
- `vaultdraw://cmd` links run only an allow list of safe commands.
- A community plugin cannot take an official plugin's id or a built-in command group name, and a plugin that has never run always asks first.

### Faster and lighter

- Everyday use (three small drawings, packaged, foreground, quiet machine) peaks at about 470 MB in total and idles near 250 MB. Most of the peak is WebKit's display buffers for the editor canvases.
- `memory.low_memory_canvas = true` lowers that peak to about 365 MB, at about 60 instead of 120 frames per second while panning. It is off by default.
- A 5,000-drawing vault peaks above 1 GB, varying by about 250 MB from run to run.
- Startup work is yours to schedule: `search.start`, `links.start`, `history.start` and `files.list_start` choose on open, when idle, or on first use.

### Known limits

- The macOS build is unsigned: right-click, Open the first time.
- Linux builds are new and were smoke-launched under a virtual display, not on every desktop.
- Plugins and the plugin API are experimental. The community plugin list (`Vaultdraw/plugin-registry`) is published but has no plugins yet, so Browse is empty. There is no automatic update.
