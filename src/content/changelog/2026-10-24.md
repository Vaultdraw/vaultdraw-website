---
title: Version 0.2.0, more details
date: 2026-10-24
---

These smaller changes are part of version 0.2.0. They are not in 0.1.2.

### New

- **Key sequences and which-key.** A key in `[hotkeys]` can be several chords, such as `"g g"` or `"<leader> f f"`, with a leader key (default `Backslash`). A popup lists what can follow a half-typed sequence. Nothing is bound by default, and nothing loads until you write a sequence. The tool keys (`R`, `E`, `A` and the rest) are now commands (`tool.rectangle`, `tool.eraser`, …) with the same default keys, so they can be rebound too. See [Keyboard](/docs/keyboard/#key-sequences-leader-and-which-key).
- **Key group names.** **Settings → Hotkeys → Key group names** names a group of sequences, which the which-key popup shows. It writes `[keys.labels]` for you and keeps your comments.
- **`vaultdraw://` links.** Open a drawing or vault, start a search, create a drawing or run a palette command from a note, a web page or a script. Opening and searching run at once. Switching vault, creating a drawing and running a command ask first. `vaultdraw uri <url>` does the same from Terminal. `control.uri_enabled = false` turns links off. See [Links and files from outside](/docs/links-from-outside/).
- **Open With Vaultdraw.** Finder lists Vaultdraw for `.excalidraw` drawings and `.excalidrawlib` libraries (your default app is not changed). A file outside every vault asks: copy it into the vault, open its folder as a vault, or cancel. On Linux, the palette command **Links: Register Vaultdraw for links and files (Linux)** sets it up.
- **`vaultdraw export`.** Renders a drawing to PNG, SVG or PDF through the running app, to a file, a folder or stdout, and never replaces a file unless you pass `--force`. A folder exports with `--out-dir`, one frame with `--frame`. See [Control the app](/docs/cli-app/#export-a-drawing).
- **File tree and list keys.** `j`/`k` move, `h`/`l` close and open folders, Enter opens, `r` renames, `a` creates, `d` deletes, `m` moves, **Cmd+Option+F** focuses the tree. The Tags list, Links panel and Settings list use the same `list.*` commands, which can be rebound. See [Keyboard](/docs/keyboard/#file-tree-and-list-keys).
- **Gallery and graph keys are commands.** `gallery.*` and `graph.*` can be rebound in `[hotkeys]`. `graph.fit` now has the default key `0`. See [Keyboard](/docs/keyboard/#gallery-and-graph-keys).
- **Settings no longer rewrites `config.toml`.** What you change in Settings, `vaultdraw config set` and the control API is saved to `overrides.toml` in the state folder, and it wins over `config.toml`. Your file keeps its comments and layout, and nothing is migrated. A chip beside each setting says where its value comes from, and **Settings → General → Config files** lists both files. See [Layers](/docs/configuration/#layers).
- **Check your config.** `vaultdraw config check` reports every problem with file, line and column, and suggests the right name for a typo. `vaultdraw config schema` gives editors a JSON Schema for completion. `vaultdraw doctor` prints a read-only report for bug reports. All three work with the app closed. Keys the app doesn't know are now reported instead of silently ignored. See [Check your config](/docs/configuration/#check-your-config).
- **`[include]` in `config.toml`.** Pull in other TOML files or folders, to split a config or share part of it. Nothing loads unless you name it. See [Including other files](/docs/configuration/#including-other-files).
- **CSS snippets.** Put `.css` files in `snippets/` in the config folder and turn each on in **Settings → Appearance** or with `appearance.snippets`. They apply after the theme, reload live and never change drawings or exports. See [Themes](/docs/themes/#css-snippets).
- **An AI switch, off by default.** `ai.enabled` and `ai.mcp_enabled` decide whether an AI app you connect may read and edit your drawings. Turning it on shows a warning first, and turning it off applies at once. **Settings → Control** has the switch. See [AI](/docs/configuration/#ai).
- **Read and edit the drawing on screen.** `vaultdraw scene read`, `get`, `selection` and `apply` work on the open drawing. One `apply` is one undo step. Experimental. See [Control the app](/docs/cli-app/#read-and-edit-the-drawing-on-screen).
- **Plugin scene writes.** A plugin can add boxes, bind arrows to them and group them in one undo step (plugin API 0.4.0). `plugins.scene_max_ops` caps one batch. See [Plugins](/docs/plugins/#writing-a-plugin).

### Faster

- **Memory comes back after you delete images.** Image data that no undo or redo step can restore is freed about 20 seconds after you stop editing. Saved drawings do not change. New keys: `memory.free_unused_images` (default on) and `memory.undo_steps` (default 1000; undo was unlimited before). See [Settings](/docs/settings/#memory).
- **Faster first search.** `vaultdraw search` and the first in-app search on a vault with no index take about 240 ms instead of 360 ms on 5,000 drawings, with 20 to 30 percent less CPU. See [Search](/docs/search/#the-search-index).
- **Thumbnails for bigger drawings.** `interface.thumbnail_max_elements` (default 8000, was a fixed 2,500, range 100 to 50000) sets the biggest drawing that gets a thumbnail. It applies live. See [Configuration](/docs/configuration/).

### Changed

- **Faster start.** Only eight built-in colour themes are part of the startup code. The others load when you pick one, and the configured theme loads before the first paint. The theme code read at startup shrinks from 210 KB to 67 KB. See [Themes](/docs/themes/).
